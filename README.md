# HackAlem AI — консольный прототип

Программа читает общий каталог `data/catalog.sqlite3`,
запрашивает параметры мероприятия и выводит **до трёх реальных записей из файла**.
Описания анализирует **уже обученная нейросеть**
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
Это не TF-IDF, не случайная сортировка и не вызов LLM с `temperature=0`.

## Статус проверки — прочитайте перед демонстрацией

Реальная модель загружена и проверена на Windows. Проверены веб-подбор,
одновременные запросы и повторяемость результатов. Автоматические тесты включают
интеграционные проверки настоящей модели и проверки надёжности сервисов.
Это не заменяет оценку полезности рекомендаций людьми: см. [методику](docs/EVALUATION.md).

Сайт и консоль используют одну SQLite-базу. CSV/JSONL используются для импорта
или явно заданного отдельного запуска с `--catalog`. Обновление общего каталога:

```powershell
.\.venv\Scripts\python.exe -m scripts.import_catalog data/catalog.csv
```

Импорт заменяет весь каталог после проверки данных. Подробности — в
[инструкции сайта](docs/WEB_README.md).

В архиве нет весов и установленных библиотек. При первом запуске программа
загружает фиксированные веса и токенизатор (около 127 MB суммарно); для установки
Python-библиотек нужен дополнительный трафик. После подготовки inference
работает локально, без API-ключей, регистрации, оплаты и отправки каталога на сервер.
Если модель недоступна, программа выдаёт ошибку; скрытого перехода на «ИИ из if» нет.

## Быстрый запуск на Windows

Нужен **Python 3.11–3.13, 64-bit** (подойдёт уже установленный Python 3.13).
Распакуйте архив. Откройте папку `hackalem_ai_console`.

Самый простой путь — запустить `scripts/run_windows.bat` двойным щелчком.
Скрипт создаёт `.venv`, устанавливает зависимости, скачивает/проверяет модель,
сохраняет векторы описаний и открывает консольную форму. Системные настройки
Windows и PowerShell ExecutionPolicy он не меняет.

Альтернативный запуск из терминала VS Code / PowerShell в папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r requirements.txt
.\.venv\Scripts\python.exe main.py --prepare
.\.venv\Scripts\python.exe main.py
```

Активация окружения не нужна. После первого успешного запуска:

```powershell
.\.venv\Scripts\python.exe main.py --offline
```

Если `py` не найден, первую команду можно заменить на `python -m venv .venv`.
Не запускайте файлы прямо внутри ZIP.

## Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --prepare
.venv/bin/python main.py
```

Для этой версии целевая конфигурация — Windows/Linux x86-64 с CPU.
ARM и другие платформы отдельно не проверены.

## Что вводить в консоли

Пример с несколькими кандидатами из вашего файла:

```text
Город: Алматы
Категория: Ведущий
Дата: 14.11.2026
Тип мероприятия: корпоратив
Бюджет: 1200000
Длительность: 6
Язык: русский
Пожелания: Интеллигентный юмор, импровизация, общение с гостями без банальных конкурсов
```

Под городом, категорией и форматом можно ввести номер из меню или название.
Enter принимает предложенное значение в квадратных скобках.
Пустые длительность/язык/пожелания означают отсутствие дополнительного ограничения.
Дата: `2026-11-14` или `14.11.2026`; бюджет: `1200000` или `1 200 000`;
длительность: `6`, `6.5` или `6,5`. `выход` завершает ввод.

Пожелания — дополнительное мягкое предпочтение для сравнения смысла.
Например, «без конкурсов» влияет на смысловую близость, но не становится
подтверждённой характеристикой исполнителя: нейросеть может неверно понимать
отрицания. Обязательные ограничения проверяются только структурированными полями.

В карточке: ID, имя, категория, город, стартовая цена, смысловая оценка,
объяснение по фактам и выделенный моделью исходный фрагмент описания.
Число `semantic_score` — **не вероятность**, не рейтинг качества и не рекомендация
заключать договор. Положительные утверждения описания — самоописание профиля,
а не независимая проверка.

Если подходящих 4 или больше — показываются первые 3. Если 1–2 — показываются
только они с причиной. При нуле явно различаются «нет категории в городе» и
«кандидаты есть, но не проходят условия». Подрядчики не придумываются.

## Запрос из JSON и другие команды

```powershell
.\.venv\Scripts\python.exe main.py --query examples\dense.json
.\.venv\Scripts\python.exe main.py --query examples\rare.json
.\.venv\Scripts\python.exe main.py --query examples\busy.json
.\.venv\Scripts\python.exe main.py --demo
.\.venv\Scripts\python.exe main.py --list-options
```

В JSON используются поля `city`, `event_date`, `event_format`, `category`,
`budget_kzt`, `hours`, `language`, `preferences`. Последние три необязательны.
В `examples/` находятся восемь готовых запросов, а не заготовленные AI-ответы.
`reports/validation_report.json` содержит только проверенные результаты строгих фильтров,
без выдуманных оценок или AI-ранжирования.

Машиночитаемый результат:

```powershell
.\.venv\Scripts\python.exe main.py --query examples\dense.json --json
```

Служебные сообщения о скачивании уходят в stderr, поэтому stdout остаётся JSON.

Другой CSV/JSONL с такой же схемой:

```powershell
.\.venv\Scripts\python.exe main.py --catalog "C:\path\to\catalog.csv"
```

`data/catalog.csv` — побайтовая копия загруженного вами файла. Исходные данные
не модифицируются. Изменения файла нужно импортировать командой выше.
Сайт увидит новый каталог при следующем запросе, консоль — при следующем запуске.
Новые данные автоматически меняют ключ результатов в кэше.

## Где именно работает обученный ИИ

1. Код читает поля и отбирает нужные город/категорию.
2. Код исключает занятых, слишком дорогих, не берущих формат, а при наличии
   требований — не подходящих по языку/длительности.
3. **Нейросеть** переводит запрос и фрагменты описаний прошедших кандидатов
   в 384-мерные числовые векторы. Длинные описания разбиваются на фрагменты,
   а не просто обрезаются до первого абзаца.
4. Код считает косинусную близость. Итоговая формула:
   `0.7 * максимальная близость фрагмента + 0.3 * средняя близость фрагментов`.
5. Порядок: оценка по убыванию (6 знаков), стартовая цена по возрастанию,
   затем ID по возрастанию. Цена используется только при одинаковой оценке.
6. Объяснение: проверенные факты и исходный фрагмент, выбранный нейросетью.
   Генерации неподтверждённых фактов нет.

Для длинного запроса векторы его фрагментов усредняются и нормируются.
Входы модели имеют длину 128 токенов, фиксированный padding; batch size = 1.
Среднее по выходам токенов берётся с учётом attention_mask, затем применяется
L2-нормализация. Во время подготовки индексируются все профили;
при обычном запросе анализируются только допустимые кандидаты.

Веса обучены авторами модели заранее. На 66 строках нового supervised-обучения
не делается: в датасете нет меток «запрос → правильный подрядчик», а задание
прямо исключает такое дообучение. Формула 0.7/0.3 — инженерное правило прототипа,
не обученная на пользовательских оценках модель ранжирования.

## Повторяемость

При одинаковых нормализованных параметрах, неизменных данных/коде/модели и
одинаковом окружении возвращается тот же состав, порядок, оценки и объяснения.

Меры в коде: нормализация ввода; фиксированный commit модели и SHA-256 файлов;
зафиксированные основные зависимости; CPU, последовательный режим и один поток;
одинаковые длина входа и размер batch; округление оценки; устойчивые правила
разрешения равенства; отсутствие случайной выборки и генеративной LLM;
постоянный кэш ответа и векторов. Ключ ответа включает запрос, каталог,
версию модели/библиотек и исходный код.

**Не обещается побайтовая численная идентичность после смены CPU, runtime,
версии Python/библиотек, данных или модели.** Кэш нельзя считать способом
сохранить корректность при смене данных; при изменении данных он инвалидируется.

Проверка настоящей модели в двух независимых процессах, **без чтения и записи
постоянного кэша**:

```powershell
.\.venv\Scripts\python.exe scripts/check_determinism.py
```

Команда требует заранее выполненного `main.py --prepare`.
Она возвращает `PASS` только если JSON полностью совпадает и модель реально
использовалась. В архив не включён ложный лог об успешном прохождении этой проверки.

## Тесты

Обычные тесты, доступные даже без скачанной модели:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Сохранённый отчёт исходной сборки содержит 46 пройденных тестов и 4 пропущенных.
Для актуальной проверки выполните команды ниже; сейчас модель доступна локально.
`tests/test_core.py` содержит тестовую замену векторизатора исключительно
для изоляции логики. Приложение её никогда не импортирует.

После скачивания весов — полный набор с реальной моделью:

```powershell
$env:RUN_AI_TESTS="1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:RUN_AI_TESTS
```

`reports/test_results.txt` — фактический лог тестов, выполненных при сборке.
Интеграционные проверки: размерность/норма настоящего эмбеддинга; русскоязычная
семантическая smoke-проверка; разбиение всех описаний в окно токенов;
повторяемость результата в двух новых сессиях модели.

## Ограничения каталога и честные ответы

Календарь только 23.09.2026–31.12.2026, без внешних календарей.
Пустой `max_hours` означает неприменимость длительности присутствия, не ноль.
`price_from_kzt` — стартовая цена за мероприятие, не почасовая ставка.
`synthetic`, `price_imputed`, `city_imputed` сохраняются и отображаются.
Текст описания не переопределяет `event_formats`, `languages`, `city` или календарь.
Язык в форме — один обязательный язык, а не язык интерфейса; интерфейс русский.
Если обязательных кандидатов нет, модель не запускается и `ai_used=false`.
Семантический порог не применяется: выбираются наиболее близкие из допустимых,
даже когда свободные пожелания не подтверждаются в описаниях.
Скорость до 10 секунд не измерена на реальной модели; сначала прогрейте индекс
через `--prepare` и проверьте работу на компьютере, используемом для защиты.
